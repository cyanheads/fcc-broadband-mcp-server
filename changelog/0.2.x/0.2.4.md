# 0.2.4 — 2026-10-08

Maintenance release on [@cyanheads/mcp-ts-core](https://www.npmjs.com/package/@cyanheads/mcp-ts-core) `^0.13.6 → ^0.13.14`, plus a multi-arch Docker build fix and packaging updates.

## Changed

- **Argument repair covers more representations** — an integer sent for a string ID (e.g. a `geography_ids` GEOID) is repaired to its digits (0.13.9); a numeric or boolean string, a lone string for a list, and `null` at an optional key are repaired (0.13.14). Each was previously rejected as `InvalidParams`.
- **Tool error results carry `data.requestId`** and close with `request <id>` (0.13.10), the ID the server's log records for that call carry.
- **Stack traces (0.13.7), request context (0.13.8), and `data.rootCause` (0.13.13) stay out of error data.**
- **`tech_filter` documents every code on `fcc_get_coverage_summary`, `fcc_compare_areas`, and `fcc_find_underserved`** — `acfosw` means every technology, not "any wired or fixed wireless", and `fcc_find_underserved` previously listed only `f` and `c`; `a`, `o`, `s`, and `w` are now described on all three.
- **`fcc_find_underserved`'s empty-result notice adds `Dropping state="<XX>" searches nationwide.`** when a `state` was given.
- **Tool handlers drop their `ctx.recoveryFor` forwards** — the framework fills the same `data.recovery.hint` from each declared contract entry.
- **`MCP_FORCE_CONSOLE_LOGGING` is dropped from the Dockerfile**, where nothing read it.
- **`package.json`** gains a `start` script and a `!dist/*.mcpb` `files` entry that keeps a built bundle out of the npm tarball.
- **`.gitignore` ignores every `.env*` file** except `.env.example`, `.env.template`, and `.env.sample`; `.dockerignore` excludes `.env*` and the MCP Registry token files from the build context.
- **`.mcpbignore` excludes `/docs/idea.md`, `/logs/`, `/.cache/`, and `/tests/`** from the `.mcpb` bundle.
- **CodeQL runs one job per language**, uploading under `/language:<language>` so alerts raised by default setup close once the code is fixed.
- **Scripts synced from the framework** — `lint:packaging` gains Dockerfile build-platform, `server.json` launch-shape, and `manifest.json` version checks; `lint:mcp` fails on a definition that does not load; `release:github` validates the tag before publishing.
- **`.env.example` documents** `MCP_HTTP_MAX_BODY_BYTES`, the opt-in `MCP_REQUEST_STATE_KEY` and `LOG_TOOL_FAILURE_PAYLOADS`, and the per-signal OTLP endpoint variables; `MCP_HTTP_HOST` defaults to `127.0.0.1`.
- **README capability reference rewritten** — each tool, resource, and prompt entry states its inputs, output fields, and typed failures. `CLAUDE.md`, `AGENTS.md`, and `framework-skills/` are resynced to 0.13.14.

## Fixed

- **Multi-arch Docker builds no longer run Bun under QEMU** — production dependencies install in a build-platform `deps` stage that cross-installs with `--os`/`--cpu`, runs `scripts/install-otel.ts`, and prunes musl-only packages with `scripts/prune-musl-packages.ts`.
- **`server.json` npm entries launch through `npx`** — the `run start:*` arguments are gone, and the HTTP entry sets `MCP_TRANSPORT_TYPE=http`.
