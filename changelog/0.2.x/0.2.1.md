# 0.2.1 — 2026-08-13

## Added

- **`fcc_list_downloads` pages its file manifest** ([#28](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/28)) — new `limit` (default 50, max 200) and `offset` inputs replace the prior unbounded response. `totalFiles` now counts every file matching the filters rather than just the page, and new `offset`/`pageSize`/`count`/`nextOffset`/`truncated` enrichment fields report where each page sits.

## Fixed

- **`fcc_geocode_block` resolves against 2010 census boundaries** ([#20](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/20)) — the FCC Area API defaults to 2020 blocks, which don't align with the Form 477 deployment table's 2010 block IDs, so an unpinned lookup fed `fcc_search_availability` a `blockFips` that matched no row. The request now pins `censusYear=2010`, and the output gains a `censusVintage` field confirming it.
- **`tech_filter` accepts and correctly labels the complete Form 477 technology taxonomy** ([#24](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/24)) — `fcc_search_availability` and `fcc_search_providers` previously accepted only 10 of the dataset's 14 technology codes and mislabeled three DOCSIS tiers (`41`, `42`, `43`); both now validate against the shared `TECH_CODES` list and the corrected `TECH_CODE_LABELS`.
- **The geography-summary resource rejects a GEOID that identifies no geography** ([#25](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/25)) — previously a nonexistent GEOID returned segments-derived zero coverage, indistinguishable from a real geography with zero population. It now validates GEOID digit-count shape per type (matching `fcc_compare_areas` and `fcc_get_coverage_summary`) and throws `notFound` when the FCC Area Table has no rows for the GEOID at all.
- **`fcc_list_downloads`'s `as_of_date` is validated before it reaches the BDC API** ([#27](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/27)) — a date that isn't on the calendar or predates the first BDC period (`2022-06-30`) is now rejected without needing credentials; a well-formed date BDC doesn't publish is rejected once credentials allow the published set to be read, memoized for an hour. Previously only a `YYYY-MM-DD` format check ran, so any other malformed or unpublished date reached the live API unfiltered.
