# 0.1.14 — 2026-08-13

## Changed

- **`min_unserved_pop` now defaults to `1`, not `0`** ([#17](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/17)) — fully covered areas no longer rank in a list of underserved ones by default. Set it to `0` to rank every area; the response then discloses how many returned rows are fully covered and why.

## Fixed

- **`fcc_find_underserved`'s `state` filter rejects an unrecognized code instead of silently searching nationwide** ([#15](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/15)). `STATE_ABBR_TO_FIPS` also gained the five inhabited territories (`AS`, `GU`, `MP`, `PR`, `VI`), so a real territory code no longer gets rejected alongside bogus ones.
- **`fcc_find_underserved`'s area scan no longer caps silently at 5,000 rows** ([#22](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/22)). `getAreaStatsByType` now scans to the shared 50,000-row mirror ceiling and reports `scanTruncated`/`scanRowCap` in enrichment and the response notice when it stops short, instead of ranking a silent prefix.
- **`fcc_compare_areas` ranks `coverage_pct` and `competitive_pct` worst-first**, matching `unserved_pct` and `unserved_pop` ([#23](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/23)). Rank 1 is now the lowest-coverage or lowest-competition area under those two metrics rather than the highest; the `sort_by` description and the rendered table header both state the direction.
