# 0.1.7 — 2026-06-04

## Fixed

- **`fcc_compare_areas`**: wrong error reason `invalid_all_states_combo` reused when no `geography_ids` provided and `compare_all_states=false` — now throws `missing_geography_ids` with the correct recovery hint. ([#7](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/7))
- **`fcc_search_availability`**, **`fcc_get_coverage_summary`**, **`fcc_get_provider`**: domain not-found errors were thrown from service methods via `notFound()`, omitting `data.recovery.hint` on the wire. Guards moved to handlers using `ctx.fail()` + `ctx.recoveryFor()` so recovery hints are always populated. ([#9](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/9))
- **`fcc_geocode_block`**: `block_not_found` thrown from `GeoApiService.findBlock` via `notFound()`, bypassing `ctx.fail()`. Service now returns `null` for no-block coordinates; handler throws typed `block_not_found` with recovery hint. ([#10](https://github.com/cyanheads/fcc-broadband-mcp-server/issues/10))
